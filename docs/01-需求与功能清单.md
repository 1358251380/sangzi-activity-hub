# 01 · 需求与功能清单

> 本文从项目自身视角定义「要解决什么问题、做到什么程度」，每条功能都带**验收标准**，用于对照测试记录。
> 实现落点见 §6。

---

## 1. 用户与场景

| 角色 | 谁会用到 | 典型场景 | 关键诉求 |
|---|---|---|---|
| **浏览者（同学）** | 全校学生 | "下周二有什么讲座？""这个比赛几号截止报名？" | 一眼看到**时间**，能搜到、能筛到 |
| **发布者·学院** | 学院教务 / 学生会 | 发布学科竞赛、讲座 | 信息权威、覆盖面广 |
| **发布者·学生组织** | 社团、学生会部门 | 发布活动安排、招新 | 长期可见、能持续更新 |
| **发布者·个人** | 任何同学 | 转发自己知道的机会 | 门槛低、一次录入 |
| **评论者** | 浏览者兼任 | "报名要交什么材料？""去年这题考了啥？" | 补充报名经验，靠近关键信息 |

**核心用户旅程**：

```
发现活动 → 看时间是否冲突 → 看报名截止还有多久 → 看详情/参与方式
        → 看别人评论（材料/难度/经验） → 决定报名
```

这条旅程上有三个断点，也就是本项目的三个设计焦点：

**聚合（一处看全）→ 时间（是否来得及 / 是否冲突）→ 交流（值不值得去）**

## 2. 核心功能（P0）

P0 的含义：不做完，系统就不成立。

### F1 活动浏览列表

| 项 | 内容 |
|---|---|
| 要求 | 卡片/列表展示，含名称、类型、发布者、开始时间、结束时间、报名截止时间；能区分发布者是学院 / 学生组织 / 个人 |
| 验收标准 | ① 首页卡片同时可见上述字段 ② 发布者类型有**视觉上可区分**的标签（颜色 + 文案），不依赖文字细读 ③ 报名截止与活动起止**视觉上分离**，不被误读为同一时间 |

### F2 活动详情

| 项 | 内容 |
|---|---|
| 要求 | 详情含活动介绍、参与方式或相关链接；示例数据需注明 |
| 验收标准 | ① 展示完整介绍与链接（可点击、新窗口打开） ② 页面标注"示例数据" ③ 展示报名截止倒计时 / 相对时间 |

### F3 时间轴（核心）

| 项 | 内容 |
|---|---|
| 要求 | 按时间展示活动，**体现持续跨度**；**报名截止与举办时间是两个不同的时间**，必须区分 |
| 验收标准 | ① 多日活动色条长度与天数成正比，跨天可见跨度，**不能退化成普通列表** ② 报名截止以**独立标记**（形状区别于色条）呈现 ③ 典型多日竞赛（10/20 截止、11/15–16 举行）在时间轴上同时可读 ④ 可切换时间窗口（周/月/季），有今天基准线与图例 |

### F4 活动发布

| 项 | 内容 |
|---|---|
| 要求 | 表单含：名称、类型、发布者类型、发布者名称、面向对象、开始时间、结束时间、报名截止时间、活动介绍 |
| 验收标准 | ① 9 个字段齐全 ② 校验规则全部生效（见下表） ③ 身份用下拉选择，不做真实账号 ④ 提交成功有明确反馈并跳转 |

**校验规则（服务端为准，前端同步提示）**

| 规则 | 提示文案 |
|---|---|
| 必填项为空 | "「活动名称」不能为空" |
| 结束时间早于开始时间 | "结束时间不能早于开始时间" |
| 报名截止晚于活动结束 | "报名截止时间不能晚于活动结束时间" |
| 名称超长（>100 字） | "活动名称不能超过 100 字" |
| 介绍超长（>5000 字） | "活动介绍不能超过 5000 字" |
| 评论内容为空 | "评论内容不能为空" |
| 评论超长（>500 字） | "评论内容不能超过 500 字" |

### F5 搜索与筛选

| 项 | 内容 |
|---|---|
| 要求 | 关键词搜索 + 多维度筛选，条件可组合 |
| 验收标准 | ① 关键词同时匹配标题与介绍正文 ② 活动类型筛选 ③ 发布者类型筛选 ④ 面向对象筛选 ⑤ 可排序、可一键清空、结果为空有友好提示 |

### F6 评论与注意事项

| 项 | 内容 |
|---|---|
| 要求 | 详情下可查看 / 发表评论；含昵称、内容、发表时间；内容非空 |
| 验收标准 | ① 评论按时间倒序，显示昵称 / 内容 / 时间 ② 发表后立即出现，无需刷新 ③ 空内容被拒并提示 ④ 评论数在列表卡片可见 |

### F7 数据保存与可用性

| 项 | 内容 |
|---|---|
| 要求 | 操作后有明确提示；刷新后数据不丢；导航清晰；桌面可用，窄屏可读 |
| 验收标准 | ① **刷新页面后新增活动与评论仍在** ② 所有写操作有成功 / 失败提示 ③ 顶部导航常驻，可直达主页面 ④ 1440px 下无横向滚动 ⑤ 375px 下页面无横向溢出 |

## 4. 明确不做的范围

| 项 | 理由 |
|---|---|
| 真实账号 / 登录 / 鉴权 | 本项目的价值在信息聚合与时间呈现，不在身份体系。发布时选一个身份即可覆盖需求，引入账号会带来会话、密码、找回等一整套与目标无关的复杂度 |
| 对接学校系统 / 统一身份认证 | 依赖外部系统与授权，无法在本地完整复现，也无法验证 |
| 真实通知推送 | 需要短信 / 邮件通道，属于外部依赖 |
| 收集报名名单 | 涉及真实个人信息，不适合在任何示例项目中实现 |
| 服务器采购 / 公网部署 | 不是本项目要验证的能力 |

## 5. 非功能需求

| 维度 | 要求 | 验证方式 |
|---|---|---|
| 性能 | 读接口 P95 < 10ms（本机基线 P95 2.5ms） | 实测基线见 [docs/12](12-容量基线与压测.md) |
| 数据量 | 种子数据 ≥ 12 条，覆盖全部时间边界场景 | 见 [docs/03 §5](03-时间轴设计说明.md) |
| 时区 | 存储用 UTC ISO，展示按本地时区 | 单测 |
| 可用性 | 后端异常返回结构化错误，前端不白屏 | 错误注入测试 |
| 可维护性 | 核心纯函数（校验 / 状态 / 时间轴坐标）有单测 | `npm test` |
| 可运行性 | 新机器按 README 步骤启动成功 | 三种启动方式均已实测 |
| 可观测性 | 每个请求有 requestId，日志可结构化采集 | [docs/04 §3.2](04-部署与质量方案.md) |
| 可恢复性 | 备份可还原，且还原流程演练过 | `npm run backup:drill` |
