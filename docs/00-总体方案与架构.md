# 00 · 总体方案与架构

> 校园活动聚合与时间轴系统
> 侧重：**服务器与部署**（运维方向）

---

## 1. 项目定位

把分散在公众号、QQ 群、微信群里的校园活动信息聚合到一处，**以时间为第一主轴**呈现，并允许同学在活动下沉淀报名经验与注意事项。

本项目的判断是：这类系统真正难的不是功能数量，而是**设计决策是否站得住、工程是否完整**。因此实现上刻意避免堆功能，把精力放在数据模型、时间轴算法与可验证性上。

## 3. 技术方案（已定，理由见下）

```
┌──────────────────────────────────────────────┐
│  web/          前端 SPA                      │
│  React 19 + Vite + 原生 CSS（设计令牌）       │
│  React Router   数据请求：原生 fetch 封装     │
└───────────────────┬──────────────────────────┘
                    │ HTTP /api/*  (JSON)
                    │ 开发期 Vite proxy → :3001
┌───────────────────▼──────────────────────────┐
│  server/       后端 API                      │
│  Node 24 ESM + Express 5                     │
│  数据层：node:sqlite（内置，单文件 DB）        │
│  校验：自写 validate.js（零依赖）              │
│  日志：自写 request-logger 中间件              │
└──────────────────────────────────────────────┘
                    │
              data/app.db  (SQLite 单文件)
```

### 3.1 为什么是这套

| 决策 | 理由 |
|---|---|
| **前后端分离** | 前端只负责渲染与交互，业务规则与数据全部收在 REST 接口后面。校验、状态派生、查询都能脱离 UI 单独测试，也便于将来替换任一端 |
| **SQLite 而非 MySQL/PG** | 单文件、零运维、别人 clone 下来直接跑；不需要额外部署数据库服务 |
| **`node:sqlite` 而非 better-sqlite3** | 内置模块，**免原生编译**，Windows 上不会因 node-gyp/VS Build Tools 失败。这是本机取证后的选择 |
| **Express 5** | 生态最稳、代码量最小。实测可安装 |
| **无 TypeScript** | 运维方向不需要构建步骤来证明工程能力；**零构建 = 后端 `node src/index.js` 直接跑**，降低"别人照着跑不起来"的风险。类型用 JSDoc 表达 |
| **React + Vite** | 时间轴、月历这类富交互用声明式渲染成本最低；Vite 构建产物可直接由后端托管，**生产环境单进程单端口**，运维面更干净 |
| **原生 CSS 设计令牌** | 不引 UI 框架：包体小、样式可控、避免"套模板"观感，且 CSS 变量本身就是一份设计规范文档 |

### 3.2 被否决的方案（写进 README 的"设计选择"）

| 方案 | 否决原因 |
|---|---|
| 纯前端 + localStorage | 数据层与业务规则全部堆在浏览器里，无法独立测试，也难以扩展 |
| Next.js 全栈一体 | 部署最简单，但"前后端分离"的加分叙事被削弱；且 SSR 对本题无收益 |
| Python FastAPI + SQLite | 同样合格，但会引入第二套运行时，增加启动说明复杂度，运维面反而更重 |
| TypeScript 全栈 | 增加 build/tsc 环节与"跑不起来"的失败模式，收益不足以抵消风险 |

## 5. 运行方式（三种，按依赖从轻到重）

| 方式 | 命令 | 依赖 | 本机可验证 |
|---|---|---|---|
| A. 本地开发 | `npm run dev` | Node ≥ 22.5 | ✅ |
| B. 生产模式 | `npm run build && npm start` | Node（单端口 3001 托管前端产物） | ✅ |
| C. 容器 | `docker compose -f deploy/docker-compose.yml up -d --build` | Docker Desktop | ✅ 已验证（构建 30s / healthy / 重启后数据仍在） |

**默认交付 B 与 C**：B 保证"别人能照着跑起来"，C 展示运维能力。
