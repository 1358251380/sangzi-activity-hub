### 8.2 Nginx 网关

| 检查 | 实测 |
|---|---|
| 容器状态 | ✅ `sangzi-app` healthy、`sangzi-gateway` healthy |
| HTTP 入口 `:8080` | ✅ 200 |
| HTTPS 入口 `:8443`（自签） | ✅ 200，`Strict-Transport-Security: max-age=31536000` |
| 安全响应头 | ✅ `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy`、`Permissions-Policy` |
| 版本号隐藏 | ✅ `Server: nginx`（无版本号） |

| **后端端口隔离** | ✅ 宿主无法连接 `3001`（应用只 `expose`，不 publish） |

### 8.3 跨层请求追踪

同一 `requestId` 出现在 nginx access log 与 app 日志：

```
nginx: {"reqId":"d64109e68d1b3b102c105e9289fc9a77",...,"rt":0.004,"upstream":"172.18.0.3:3001"}
app  : {"reqId":"d64109e68d1b3b102c105e9289fc9a77","m":"GET","p":"/api/activities","s":200,"ms":4.3}
```

交叉统计：nginx 侧 83 个 id，应用侧 45 个，**共有 45 个完全匹配**（差额 38 正是被限流的请求）。

### 8.4 容量基线

| 场景 | 并发 | RPS | P50 | P95 | P99 |
|---|---|---|---|---|---|
| 应用直连 读列表 | 10 | 5,124.7 | 1.7 ms | 2.5 ms | 8.7 ms |
| 应用直连 读列表 | 50 | 1,944.4 | 24.7 ms | 33.0 ms | 38.0 ms |
| 应用直连 写入 | 5 | 325.9 | 14.7 ms | 19.9 ms | 27.5 ms |
| 经 Nginx 端到端 | 10 | 2,902.5 | 3.2 ms | 4.5 ms | 8.7 ms |

三个结论：**写比读慢 16 倍**（SQLite 单写者）；**并发 50 比 10 更慢**（单进程饱和，吞吐降 62%）；**反代代价约 +1.5 ms**，换来 TLS/限流/安全头，划算。

完整分析、测量边界与优化优先级见 [docs/12-容量基线与压测.md](12-容量基线与压测.md)。

### 8.5 过程中修复的部署问题

| 问题 | 原因 | 处理 |
|---|---|---|
| nginx 反复 `Restarting` | 容器创建时证书目录还不存在，之后生成的证书没被挂载进去 | `docker compose up -d --force-recreate nginx` |
| `gen-cert.ps1` 解析报错 | PS 5.1 按 ANSI 读脚本，中文 + here-string 组合触发解析失败 | 脚本改为**纯 ASCII**，并补充 Git 自带 openssl 的自动定位 |
