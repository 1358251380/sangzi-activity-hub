# 02 · 数据模型与接口设计

> 同时作为运维/研发方向选交材料「数据模型与接口设计」。
> 表结构单一事实来源：`server/src/schema.sql`

---

## 1. 设计原则

| 原则 | 说明 |
|---|---|
| **三类发布者合表** | 学院/学生组织/个人不建三张表，用 `publisher_type` + `publisher_name` 表达。否则列表聚合、时间轴、筛选都要写三份 |
| **时间全部存 UTC ISO 字符串** | `2026-11-15T01:00:00.000Z`。ISO 字符串按字典序排序 == 按时间排序，SQLite 里可直接比较、可建索引。展示层统一转 `Asia/Shanghai` |
| **状态不落库** | `status` 与 `signupOpen` 由时间字段**派生计算**。落库必然与实际时间不一致，且时间轴/倒计时依赖它 |
| **不存"是否多天"** | 由 `end_at - start_at` 派生，避免冗余不一致 |
| **评论级联删除** | 活动删除时评论随之删除，`.gitignore` 排除 `data/*.db` |

  id              INTEGER PRIMARY KEY AUTOINCREMENT,

  publisher_type  TEXT NOT NULL CHECK (publisher_type IN ('college','org','personal')),

  end_at          TEXT NOT NULL,
  signup_deadline TEXT NOT NULL,
  description     TEXT NOT NULL CHECK (length(description) BETWEEN 1 AND 5000),
  link            TEXT,
  cover_color     TEXT CHECK (cover_color IS NULL OR cover_color GLOB '#[0-9a-fA-F][0-9a-fA-F][0-9a-fA-F][0-9a-fA-F][0-9a-fA-F][0-9a-fA-F]'),
  created_at      TEXT NOT NULL,
  updated_at      TEXT NOT NULL,
  CHECK (end_at >= start_at),
  CHECK (signup_deadline <= end_at)
);

CREATE TABLE IF NOT EXISTS comments (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  activity_id INTEGER NOT NULL REFERENCES activities(id) ON DELETE CASCADE,
  nickname    TEXT NOT NULL CHECK (length(nickname) BETWEEN 1 AND 20),
  content     TEXT NOT NULL CHECK (length(content) BETWEEN 1 AND 500),
  created_at  TEXT NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_activities_start    ON activities(start_at);
CREATE INDEX IF NOT EXISTS idx_activities_end      ON activities(end_at);
CREATE INDEX IF NOT EXISTS idx_activities_type     ON activities(type);
CREATE INDEX IF NOT EXISTS idx_activities_pub      ON activities(publisher_type);
CREATE INDEX IF NOT EXISTS idx_activities_deadline ON activities(signup_deadline);

## 3. 状态派生规则（`server/src/lib/status.js`）

```js
/**
 * @returns {'signup_open'|'signup_closed'|'ongoing'|'ended'}
 */
export function deriveStatus({ startAt, endAt, signupDeadline }, now = new Date()) {
  const t = now.getTime();
  const start = Date.parse(startAt);
  const end = Date.parse(endAt);
  const deadline = Date.parse(signupDeadline);

  if (t > end) return 'ended';          // 已结束
  if (t >= start) return 'ongoing';     // 进行中
  if (t >= deadline) return 'signup_closed'; // 报名已截止
  return 'signup_open';                 // 报名中
}

/** 是否仍可报名（与生命周期正交） */
export function isSignupOpen({ signupDeadline }, now = new Date()) {
  return now.getTime() < Date.parse(signupDeadline);
}
```

| status | 中文 | 依据 |
|---|---|---|
| `signup_open` | 报名中 | now < 截止，且未开始 |
| `signup_closed` | 报名已截止 | 截止 ≤ now < 开始 |
| `ongoing` | 进行中 | 开始 ≤ now ≤ 结束（**可能仍可报名**：截止晚于开始时 `signupOpen=true`） |
| `ended` | 已结束 | now > 结束 |

> 之所以 `status` 与 `signupOpen` 分开："报名截止"与"举办时间"是两件不同的事，状态模型必须同样正交，否则活动进行中但报名还开着的情况无法表达。

## 4. 接口设计

**Base URL**：`/api`
**Content-Type**：`application/json; charset=utf-8`

### 4.1 统一错误结构

```json
{
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "表单校验未通过",
    "fields": { "endAt": "结束时间不能早于开始时间" },
    "requestId": "50fc1af134e2"
  }
}
```

| HTTP | code | 场景 |
|---|---|---|
| 400 | `BAD_REQUEST` | 参数格式错误（如非法日期、非法分页） |
| 404 | `NOT_FOUND` | 活动不存在 / 接口不存在 |
| 422 | `VALIDATION_FAILED` | 业务校验失败，`fields` 给出逐字段错误 |
| 500 | `INTERNAL_ERROR` | 未捕获异常（日志打印堆栈，响应不含堆栈） |

**`requestId`**：每次请求的唯一追踪号。

- 同时出现在三个地方：**响应头 `X-Request-Id`** ↔ **日志字段 `reqId`** ↔ **错误体 `requestId`**
- 若上游反向代理已注入合法的 `X-Request-Id`（8–64 位 `[A-Za-z0-9._-]`），服务端会复用它，从而把一次调用在多个服务间的日志串起来
- 用途：用户报「出错了」时提供这个号，运维可直接在日志里定位那一次请求及其上下文

### 4.1.1 其它响应头

| 响应头 | 值 | 说明 |
|---|---|---|
| `X-Request-Id` | 追踪号 | 所有响应都带 |
| `Cache-Control` | `no-cache` | `index.html` 与 SPA 兜底响应（发版后必须立刻拿到新页面） |
| `Cache-Control` | `public, max-age=31536000, immutable` | `/assets/*` 带内容哈希的构建产物 |
| `Content-Encoding` | `gzip` | JSON 响应在客户端支持且体积 ≥1KB 时压缩 |
| `Vary` | `Accept-Encoding` | 与 gzip 配套，避免缓存投毒 |

### 4.4 POST /api/activities

**Request**

```json
{
  "title": "第七届程序设计竞赛",
  "type": "contest",
  "publisherType": "college",
  "publisherName": "计算机学院",
  "audience": "全校",
  "startAt": "2026-11-15T09:00:00+08:00",
  "endAt": "2026-11-16T18:00:00+08:00",
  "signupDeadline": "2026-10-20T23:59:00+08:00",
  "description": "……",
  "link": "https://example.com/contest"
}
```

**成功 201**：返回创建后的完整对象（含派生字段）。
**失败 422**：`fields` 逐字段给出中文错误（文案见 01 文档 §2 F4）。

> 接口接受带时区的 ISO 8601，服务端统一 `new Date(x).toISOString()` 归一为 UTC 存储。

### 4.5 POST /api/activities/:id/comments

**Request**：`{ "nickname": "小王", "content": "报名要交作品说明，截止前一天才能提交" }`
**成功 201**：返回评论对象。**失败 422**：`content` 为空或超长。

### 4.6 GET /api/timeline

**Query**：`from`、`to`（必填，ISO date）、其余筛选项同 4.3（忽略分页）
**Response**：`{ "from": "...", "to": "...", "items": [ …ActivityDTO ] }`
只返回与 `[from, to]` **有交集**的活动：`start_at <= to AND end_at >= from`。
坐标计算在前端完成（见 03 文档），服务端只做数据筛选，保持纯数据接口。

### 4.7 GET /api/health

```json
{ "status": "ok", "db": "ok", "uptime": 1234.5, "version": "1.0.0" }
```
数据库不可用时返回 503 且 `db: "error"`——供 Docker healthcheck 使用。

## 5. 校验规则实现位置

| 规则 | 位置 | 说明 |
|---|---|---|
| 字段非空 / 长度 / 枚举 | `server/src/lib/validate.js` | 纯函数 `validateActivityInput(input)` → `{ ok, value, fields }` |
| 结束 ≥ 开始、截止 ≤ 结束 | 同上（并在 DB CHECK 二次兜底） | 双保险：应用层给友好中文，DB 层防脏数据 |
| `link` 协议白名单 | 同上（仅 `http:`/`https:`） | 防 `javascript:` 注入 |
| 前端即时提示 | `web/src/pages/Publish.jsx` | 与后端同规则，失焦即校验；**以后端返回为准** |

## 6. 安全与边界

| 项 | 处理 |
|---|---|
| SQL 注入 | 全部使用参数化语句（`db.prepare(...).run(...)`），禁止字符串拼接 SQL |
| XSS | React 默认转义；不渲染用户 HTML；`link` 用 `rel="noopener noreferrer"` |
| LIKE 通配符注入 | 转义 `\ % _`，配合 `ESCAPE '\'` |
| 请求体大小 | `express.json({ limit: '100kb' })` |
| CORS | 开发期仅放行 `http://localhost:5173`；生产同源无需 CORS |
| 个人信息 | 示例数据全部自编，不含真实姓名/学号/报名名单 |
